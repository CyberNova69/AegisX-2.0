### Hard-won gotchas (IMPORTANT for future work on this repo)
1. **MockProvider key collision**: `MockProvider.register_response(sub, ...)`
   returns the FIRST registered substring match. The alert title appears in the
   triage prompt AND the investigation prompt AND the threat-intel prompt — so
   keying triage on the alert title hijacks later stages. Key triage on its own
   intro phrase `"Please analyze the following security alert"`.
2. **Prefer known indicators**: `extract_candidate_indicators` often returns the
   internal host IP (e.g. 172.16.20.44), which is NOT in the synthetic TI store
   → reputation "unknown". Sort indicators so ones in
   `synthetic_threat_intel.get_threat_intel()` come first.
   Known store indicators: 198.51.100.{200,77,99,250,50}, 203.0.113.88, 10.0.10.2, 127.0.0.1.
3. **Use MITRE technique_id, not keyword queries.** Keyword queries resolve
   unreliably ("brute force", "masquerading" returned nothing). technique_id
   always resolves. Full 34-technique list is in
   `datasets/metadata/mitre_reference.json`.
4. **TI synthesis findings must cite empty `evidence_ids`** or grounding
   violations get logged; TI tool results do carry real IDs.
5. Investigation steps print via `step.result.data.count`; TI steps via
   `step.query_params` (indicator / technique_id / query).
6. Bash tool blocks commands containing security keywords like `rundll32` or
   `powershell` — put such probes in a .py file or read the JSON instead.

## Task 1 — automated external dataset ingestion foundation

Implemented generic source discovery → format detection → parser registry →
canonical AegisX event mapping in `ai/ingestion/`, plus
`scripts/ingest_dataset.py` and 5 representative fixtures.

### Architecture
- `discovery.py`: safe recursive discovery; skips `.git`, venvs, caches, node_modules.
- `detection.py`: extension + content sniff; formats CSV/TSV, JSON, JSONL/NDJSON,
  XML, text/log, Excel, Parquet.
- `parsers/`: one registry based BaseParser interface; CSV/JSONL/text/XML are
  incremental; JSON is whole-document; Excel/Parquet are optional deps and emit
  explicit `MissingDependencyError` rather than pretending to support them.
- `canonicalize.py`: deterministic key-variant mapping; raw source is retained,
  unmapped fields live in `attributes`; timestamp→ISO UTC, severity vocab mapping,
  typed IPs. The generic `CanonicalEvent` has a format bridge to existing
  TriageAgent alert/context/evidence input, but performs no detection/classification.
- `pipeline.py`: `ingest()` generator for large streams; `run()` is deliberately
  in-memory and documented as moderate-input/testing convenience.

### Verification
- Tests added: `tests/test_ingestion.py` + fixtures. **22 targeted passed.**
- Full regression: **255 tests passed in 5.319s.**
- CLI smoke processed 12 multi-format fixture events.
- No protected datasets regenerated or modified.

### Honest limitations for Task 2 / review
- JSON array parser is not streaming; it uses `json.load`. Parquet uses
  `pyarrow.read_table` and is also not streaming if optional dep installed.
  CSV/JSONL/text/XML and Excel(read_only) do stream.
- No mapping-confidence, ambiguity/provenance, schema validation or dedup yet;
  those belong in requested Task 2. JSONL malformed records are preserved with
  `_parse_error`, XML/JSON failures are reported per file. CSV/text decoding uses
  `errors="replace"`; binary corruption is not separately labelled.
- Canonical schema is compatible at the alert-boundary level via `to_alert_input`,
  but it is intentionally an event schema, not a clone of synthetic training schema.
