# AegisX Fine-Tuning Pipeline (v0.1)

> **Disclaimer**: This is a research-ready fine-tuning pipeline for a student SOC project.
> It produces a synthetic SOC triage model, NOT a production-grade security tool.

## Overview

This module provides a complete pipeline for supervised fine-tuning (SFT) of a
causal language model to perform SOC alert triage. The pipeline converts AegisX
v0.4 synthetic datasets into chat-format training examples and fine-tunes a model
using QLoRA (Quantized Low-Rank Adaptation).

## What is Fine-Tuning?

Fine-tuning takes a pre-trained language model and further trains it on domain-specific
examples so it learns to produce outputs in a particular format for a particular task.

In our case:
- **Task**: SOC alert triage — classify security alerts and produce structured assessments
- **Input**: Security alert + context + evidence (formatted as a user message)
- **Output**: A structured JSON `TriageResult` (classification, severity, findings, etc.)

## Why QLoRA?

**LoRA** (Low-Rank Adaptation) freezes the original model weights and trains small
"adapter" matrices alongside them. This means:
- Only ~1-3% of parameters are trainable
- Much less GPU memory required
- Training is faster
- The original model knowledge is preserved

**QLoRA** adds 4-bit quantization on top of LoRA, further reducing VRAM requirements.
A 7B-parameter model that would normally need 28+ GB VRAM can be fine-tuned with ~8 GB.

## Quick Start

### 1. Prepare the SFT Dataset

Converts the v0.4 JSONL records into model-agnostic chat format:

```bash
python -m finetuning.prepare_sft_dataset
```

This creates:
- `datasets/finetuning/v0.4/sft/train.jsonl` — 2,400 training examples
- `datasets/finetuning/v0.4/sft/validation.jsonl` — 300 validation examples
- `datasets/finetuning/v0.4/sft/conversion_metadata.json` — provenance metadata

**Note**: `test.jsonl` is NEVER loaded during preparation. It remains untouched for evaluation.

### 2. Run GPU Preflight (College PC)

```bash
python -m finetuning.gpu_preflight
```

Reports: Python, PyTorch, CUDA, GPU name/VRAM, library versions, suitability verdict.

### 3. Dry Run (Validate Config)

```bash
python -m finetuning.train_lora --dry-run
```

Validates configuration and dataset paths without loading any model.

### 4. Train (College GPU PC Only)

```bash
# First install GPU dependencies:
pip install -r requirements-finetuning.txt

# Then train:
python -m finetuning.train_lora
```

The model name in `config.yaml` should be updated based on the college PC's VRAM:
- **8 GB VRAM**: `unsloth/Qwen2.5-3B-Instruct-bnb-4bit`
- **12 GB VRAM**: `unsloth/Qwen2.5-7B-Instruct-bnb-4bit`
- **16 GB VRAM**: `unsloth/Meta-Llama-3.1-8B-Instruct-bnb-4bit`
- **24 GB VRAM**: `unsloth/Qwen2.5-14B-Instruct-bnb-4bit`

### 5. Evaluate

```bash
python -m finetuning.evaluate_model --adapter-path models/aegisx-triage/adapter
```

### 6. Inference

```bash
python -m finetuning.inference --alert path/to/alert.json
```

## SFT Dataset Format

Each training example is a JSON object with three chat messages:

```json
{
  "messages": [
    {"role": "system",    "content": "<SOC triage system prompt>"},
    {"role": "user",      "content": "<formatted security alert>"},
    {"role": "assistant", "content": "<TriageResult JSON>"}
  ]
}
```

- The **system prompt** is reused from `ai/prompts/triage/system.txt`
- The **user message** is generated by `ai/prompts/triage.py:format_triage_user_prompt()`
- The **assistant response** follows the `ai/agents/schemas.py:TriageResult` schema

## Configuration

All training parameters are in `finetuning/config.yaml`:

| Parameter | Default | Description |
|-----------|---------|-------------|
| `model.name` | `unsloth/Qwen2.5-7B-Instruct-bnb-4bit` | HuggingFace model ID |
| `model.max_seq_length` | `2048` | Maximum sequence length |
| `training.epochs` | `3` | Number of training epochs |
| `training.learning_rate` | `2e-4` | Learning rate |
| `training.batch_size` | `4` | Per-device batch size |
| `training.gradient_accumulation_steps` | `4` | Effective batch = 16 |
| `lora.r` | `16` | LoRA rank |
| `lora.alpha` | `32` | LoRA alpha (scaling = alpha/r) |
| `lora.dropout` | `0.05` | LoRA dropout |
